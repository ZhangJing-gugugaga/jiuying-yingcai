# 微信支付与支付宝双渠道接口说明

## 启用边界

V3.3 实现微信 JSAPI、支付宝手机网站支付和本地模拟的统一账单服务。默认关闭真实渠道。生产禁用模拟，限制支付宝网关为正式地址，并按两个渠道的编号格式拒绝开发夹具身份。生产支付宝成功通知还要经过正式网关签名查单。验收使用隔离数据库、临时 RSA 密钥、微信签名和加密样本、支付宝签名表单及注入的网关响应。

小程序提供两种模拟渠道。微信原生页面只调用微信的 wx.requestPayment。支付宝适配器返回签名后的手机网站收银台参数，由后续获准的网页或客户端承接。正式支付宝小程序产品、入口策略和授权范围由集团确认后选择。

## 业务流程和数据

- 支付前校验加盟商身份、账单归属、状态、整数分金额和在途申请。正式收款必须严格匹配「服务协议收款主体快照、账单收款主体、渠道商户映射、支付商户和应用」。当前部署每个真实渠道一套凭证；只有映射到该套商户及应用的协议可付。缺映射或不匹配时保留账单和只读审计，不生成支付订单。
- payments 保存业务尝试。payment_provider_orders 保存渠道、模式、支付环境、实际商户、应用、原始账单金额、币种、商户单号和合同快照关联。一个账单只有一个有效支付订单。连接失败保留处理中订单，主动查单和有界定时回查核实结果。
- 已验签回调/查询核对原订单、渠道、应用、商户和金额，再由同一事务写入流水、账单、站内通知和审计。小程序客户端成功回调只触发查单。通知表按渠道隔离且校验重复内容。失败、取消和空资金记录都可追踪。
- 到期订单先以原商户查单。微信签名的 404 ORDER_NOT_EXIST 或支付宝 RSA2 签名的 40004/ACQ.TRADE_NOT_EXIST 允许将已到期本地订单改为已取消。明确 NOTPAY 时先请求渠道关单再复查。已支付同步入账，支付中和其他异常保留待核验。关单后查实的付款，以及商户映射或账单状态变化导致无法自动入账的已确认付款，写入 payment_exceptions，供总部按原订单和渠道凭证人工对账。
- 真实退款要求已独立批准的同一实收退款申请。payment_refund_orders 独立锁定申请、原支付、原凭证、渠道、模式和整数分金额。同一申请重复确认返回既有渠道单。经过验签的最终成功在同一事务更新 refundRequests、账单退款累计、通知和审计。账单原支付状态继续保留。线下凭证登记仅处理非渠道实收。
- 支付与退款共用回查进程。每笔在途订单最多自动查 8 次，最长退避 60 分钟。第 8 次仍待确认的退款进入财务核对，授权人员可按原退款单继续查。原路退款的自动任务只查结果，首次请求结果未知时，保留原单及金额供商户平台按原编号核对。
- 总部可按笔对账，服务通过原渠道主动查询，写入 payment_reconciliation_records 与请求 ID。适配器预留渠道交易账单取得接口。渠道逐日账单下载、银行清算和财务签认等待实际商户环境验证。

## 接口

| 方法和路径 | 权限及结果 |
| --- | --- |
| GET /api/config | paymentEnabled 兼容微信能力，paymentChannels 返回 wechat、alipay、mock 的启用状态。 |
| POST /api/payments/prepay | 账户本人；billId、可选 channel（wechat 默认／alipay）、可选 simulation；需 Idempotency-Key。返回 paymentId、channel、adapterMode、expiresAt；真实微信返回 requestPayment，支付宝返回 checkout.checkoutUrl。 |
| POST /api/payments/{id}/query 或 /close | 本人、财务或管理层。确认未付款且已到期才向渠道请求关单；到期且验签查无交易时释放本地订单。两者返回 payment、bill、providerTradeState，核验到待对账收款时含 reconciliationRequired。 |
| POST /api/payments/{id}/simulate | 本地模拟且本人，outcome 为 success、failed 或 cancelled。 |
| POST /api/payments/{id}/refund | 财务或管理层；真实退款填 refundRequestId，模拟退款填 simulation 和 amountCents；需 Idempotency-Key。 |
| GET /api/payment-refunds/requests/{refundRequestId} | 财务或管理层。按业务申请读取付款渠道、已审核金额和既有渠道退款单，返回 canStart。 |
| POST /api/payment-refunds/{id}/query | 退款所属主体、财务或管理层，返回退款状态及整数分金额。 |
| POST /api/payment-refunds/{id}/simulate | 本地模拟且财务或管理层，outcome 为 success 或 failed。 |
| POST /api/payments/{id}/reconcile | 财务或管理层，按笔比较和记录渠道状态。 |
| GET /api/payments/exceptions | 财务或管理层。返回已核验但待财务对账的渠道收款异常，limit 默认为 25（1–100），offset 默认为 0。 |
| POST /api/payments/notify、/api/payments/wechat/refund-notify | 微信签名、AES-GCM 和商户核验通过后应答 204。 |
| POST /api/payments/alipay/notify、/api/payments/alipay/refund-notify | 支付宝 RSA2 表单签名、应用、商户和已知订单核对后应答 success。退款提示触发原退款单查询。 |

## 部署变量与后续签认

- 共用 PAYMENT_MERCHANT_MAPPINGS 是 JSON 对象，按协议快照中的准确收款主体名称映射渠道的 merchantId 和 appId。配置属于后端环境，勿放入客户端或源码包。
- 微信使用 WECHAT_PAY_ENABLED、WECHAT_APP_ID、WECHAT_MCH_ID、WECHAT_API_V3_KEY、WECHAT_CERT_SERIAL、WECHAT_PRIVATE_KEY_PATH、WECHAT_PAY_PUBLIC_KEY_ID、WECHAT_PAY_PUBLIC_KEY_PATH、WECHAT_PAY_NOTIFY_URL 以及 WECHAT_PAY_REFUND_NOTIFY_URL。回调地址须为正式 HTTPS，凭证仅部署在后端。
- 支付宝使用 ALIPAY_ENABLED、ALIPAY_APP_ID、ALIPAY_MERCHANT_ID、ALIPAY_PRIVATE_KEY_PATH、ALIPAY_PUBLIC_KEY_PATH、ALIPAY_GATEWAY、ALIPAY_NOTIFY_URL、ALIPAY_PRODUCT、ALIPAY_PRODUCT_AUTHORIZED。现有服务端预留 wap 产品。未签认产品能力、应用权限及实际收款主体前保持禁用。
- 020 迁移保留原实收、退款与对账流水。历史支付宝支付环境缺证时转人工核对。回退旧二进制前先关闭真实发单和回查进程，核清线上待支付、待退款及对账异常，保留 016、020 结构和新增记录。旧运行时须继续保持真实渠道禁用。

参考 [微信支付 JSAPI 官方开发指引](https://pay.wechatpay.cn/doc/v3/merchant/4012791870) 与 [支付宝手机网站支付产品说明](https://open.alitrip.com/docs/doc.htm?articleId=105288&docType=1&treeId=193)。
