# 支付及退款验证报告

**状态：本地整改及隔离验证通过，正式商户联调待验。** 本轮覆盖 Q02、Q06、Q07，并为 Q10 提供付款和退款通知的业务编号。所有网关均使用测试进程注入的签名响应，浏览器只访问本地服务。测试库、密钥及渠道订单均为隔离样本。

| 问题 | 实现与资金处理 |
| --- | --- |
| Q02 生产沙箱 | 生产停用模拟，支付宝只接受正式网关，两个渠道校验正式商户及应用编号格式。新单写入环境标识。正式支付宝成功通知须和正式网关签名查单一致才可入账。 |
| Q07 超时和晚到付款 | 状态不明确时保留在途。到期且验签确认无交易时，释放本地订单并落关闭原因。明确未支付才向渠道关单，关单回执后复查。关单后才核验到的成功、账单事实变化或收款映射变化等异常，持久化原订单、金额、币种、渠道凭证与请求编号，进入总部「支付对账异常」。重复通知、并发查单及同一渠道流水不会产生第二笔实收。 |
| Q06 退款 | 已批准申请与渠道退款单独立。总部财务和管理层从「退款处理」按审核金额确认原路退，重复确认复用同一渠道单。签名通知或查询确认成功后才计入退款。金额使用整数分核对，原实收与已付账单保留。回查最多 8 次，退避最长 60 分钟，未确认的退款保留原单并提示人工核对。付款、退款通知分别携带业务编号，渠道确认号保留独立客户展示字段。 |

## 迁移、运行和待验

改动涉及 `server/{alipay,wechat-pay,payment-providers,payments,index}.cjs`、`database/020_payment_recovery.sql`、`admin-web/{app,operations}.js`、`tests/v33-payment-closure.test.cjs`、`.env.example`、`docs/API.md`、`docs/openapi.json` 与双渠道说明。API 保留原订单及退款接口，加总部异常列表与退款渠道详情。迁移为增量，历史支付宝订单缺支付环境标识时应人工核对后再接管。退回旧运行时前停真实发单及回查，保留新增结构和记录。正式渠道默认关闭。

已验签且无法入账的收款提供总部对账凭证和查询入口。需财务核实其在商户台账中的实际去向，明确冲正或补录政策后另行处理。处于待确认的退款在达到自动回查上限后可继续人工按原单查询。若原退款请求从未到达渠道，使用原商户和原单号在商户平台核查；应用不自动补发退款。正式支付宝回调每个新的通知编号增加一次签名查单，已处理的重复通知复用记录。回查由现有进程分批执行，未增加服务或依赖。

人工走查时，在隔离环境进入「财务处理 → 退款 → 处理退款」，核对退款申请、整数分金额及渠道，确认发起后再查询渠道退款。通过同页「支付对账异常」核对晚到付款的原支付编号、渠道凭证和请求编号。正式商户联调前需取得集团确认的协议主体映射、商户资质、清算样本和退款口径。

渠道状态参考 [支付宝交易查询](https://developer.alibaba.com/docs/api.htm?apiId=757&docType=4&treeId=180)、[微信商户订单号查单](https://pay.wechatpay.cn/doc/v3/merchant/4012791859)、[支付宝退款查询](https://aipay.alipay.com/docs/vibe-pay/ai-web-app-payment-qianyi/api-list/alipay-trade-fastpay-refund-query.html) 及 [微信支付退款最佳实践](https://pay.wechatpay.cn/doc/v3/merchant/4014959631)。
