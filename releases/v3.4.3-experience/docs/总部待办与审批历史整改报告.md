# 九盈英才 V3.2 整改报告

## 交付内容

总部经营总览展示待运营审核、待财务复核、待加盟商修改、待总部补充处理。卡片从服务端查询当前任务数量，进入带队列、过滤和分页参数的链接。管理层可登记、分派和转派有业务对象的总部跟进。总部沿用墨绿与米白，原生工作台直接读取持久化待办。

月报、网点及其他业务申请、位置核验、费用调整和客服处理展示审批时间轴。每条按访问角色展开同源结构化审计。时间轴支持月报同自然月版本关联、原记录入口、分页、区分处理结果及下一责任岗位。

## 数据流

- 一次业务写入在 SQLite 事务中提交业务、责任任务、正式审计、幂等结果。已读独立写入消息。阶段切换关闭前一责任任务并保留历史。服务费调整指向实际待复核提案。升级客服工单直达管理层处理。
- 队列及详情重新校验岗位、加盟商主体、网点授权、责任人。移除区域审核权限后，旧审核请求重放收到拒绝。
- 历史更正按原业务规则新建月报版本。营业收入更正经过运营及财务复核，财务通过前保留原有效版。原月报、结算版本和汇总调整分别保留。
- 原有整数分金额、账单、服务费及统计计算继续使用既有实现。V3.2增加责任路由和只读投影。月报报送日读取既有服务端数据，审核截止空值表示待配置。
- 月度总览把当前、上月与趋势相同查询合并到一次刷新，六个独立月份请求。浏览器按会话隔离，服务端未新增缓存、依赖或第三方付费调用。

## 兼容、迁移与回退

部署前暂停旧写进程与周期作业，对 SQLite 做一致性备份。先在副本用 `node database/migrate.cjs` 执行 014、015，检查迁移记录、`PRAGMA integrity_check`、当前任务唯一性及历史审计。记录 SQLite 写锁时长后再安排生产窗口。

014 保留业务源记录、已有任务 ID 和历史。对能从业务事实确定的当前责任补齐元数据、关闭过期阶段和重复项，增加当前责任唯一索引及转派履历保护。015 增加审批事件表、索引、不可变保护，旧审批留痕读取已存证据。历史缺失字段保持空值。旧库升级和二次打开都在隔离数据库实测。

版本升级时一次切换全部写进程。若迁移后尚无业务写入，可使用迁移前完整备份恢复旧版本。已有新版写入时优先前向修复，确保新增阶段任务和审计不会随恢复旧备份而丢失。生产库容量和备份恢复时长需现场预演。

## 本地人工验收

1. 启动本地开发后端，使用总部管理层账号查看四类待办，点击卡片后核对队列和筛选。当前工作区隔离预览为 http://127.0.0.1:18880，可见四类合成验收任务。
2. 用加盟商账号提交已结束月份月报，运营退回后，在工作台、待办、消息核对同一网点和月份。消息已读后任务继续存在，重提后进入运营队列。
3. 使用有权限的账号查看月报时间轴，展开原始审计，逐条核对时间、动作、版本与意见。切换财务、区域、客服、加盟商检查限制。
4. 创建一条关联测试网点的总部跟进，按角色分派、转派、关闭。检查历史记录和当前计数。
