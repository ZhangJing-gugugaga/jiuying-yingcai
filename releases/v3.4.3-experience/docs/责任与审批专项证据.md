# 责任与审批专项证据

Q03、Q05、Q08、Q09、Q13 和 Q14 已在隔离 SQLite、本地 HTTP 以及小程序 Page 替身通过验证。真实运营数据、真实客服投递、微信模拟器及真机交互仍需在对应环境验证。

| 验收项 | 实际行为 |
| --- | --- |
| Q03、Q13 | 工作台和「我的待办」使用同一 SQL 责任筛选和详情投影。当前待办须属于本人加盟主体，且为明确分派给该主体的加盟商动作。首页包含待处理和处理中，分别最多预览 8 条。账单金额来自有权读取的关联账单。消息已读只更新消息。 |
| Q05 | 业务申请列表、详情和时间轴使用同一内部审批意见可见规则。管理层可查看各岗位意见，岗位可查看本岗位意见，申请人看到公开处理说明。位置核验结果仍供后续审批使用。 |
| Q08 | 区域岗位的月报审批时间轴同时过滤指标数值、差异和更正字段名，按请求当时的指标和审核网点授权执行。原始视图与时间轴使用同一脱敏数据。 |
| Q09 | 重复转人工保留请求审计并标记无变化，审批历史只显示真正进入待接单的事件。历史数据通过读取规则去重，保留原始事件和通用审计。 |
| Q14 | 新增网点或地址变更补件时，以归一化后的行政区、地址、坐标及照片标识判断原核验依据是否变化。仅补电话或文字说明时保留已通过的核验和核验人员及时间。证据实质变化时进入待核验。未通过的位置核验仍需由专员复核。 |

## 持久化和兼容性

迁移 `021_partner_responsibilities.sql` 根据现有归属、业务状态和历史提醒补齐已证实的加盟商责任。待付账单与可复用的客服待办保留原任务编号。总部四个队列、已存在的运营与专员任务、审批记录和原始消息保留。报送、位置资料等同时有总部跟进职责的事项，用独立责任键记录加盟商动作。旧接口 `/api/collections/businessTasks` 对加盟商复用 `/api/tasks` 的权限和投影，保留兼容的 `dueOn` 和 `resolution` 字段。旧消息按同一主体和网点恢复业务链接，打开消息时重新核对业务对象权限。

账单金额直接读取账单，计费、入账、退款和经营统计口径沿用现有逻辑。新增成本为有限的本地 SQL 读写及首页第二组分页查询，外部调用和模型成本无变化。迁移由 SQLite 单事务执行，失败由迁移执行器回滚。旧二进制混跑和生产规模的锁持有时间仍需在部署前使用目标数据库副本排演。

## 人工复核路径

1. 在隔离环境用同一加盟商账号打开工作台和「我的待办」，比对待处理、处理中计数及账单金额。读取同一条消息后重新查询待办状态，再用另一加盟商账号验证直接打开原任务编号不可见。
2. 用位置专员和运营账号顺次打开同一新增网点申请，核对各自审批意见及原始时间轴。仅改联系电话后提交，确认转回运营。再次补件时改动地址或照片，确认重新进入专员队列。
3. 仅授权订单指标给区域用户，打开含收入及订单更正的月报历史，核对列表和原始视图。以独立请求重复转人工，检查业务时间轴只有一次待接单事件。
