# 角色权限、地图证据、负责人换绑与客服验收

副本范围内已完成并验证。按 V3.1 的《角色权限矩阵与数据可见性》和《完整验收场景与反向测试》核对 T03–T05、T11、T14 中的后端权限和数据归属。验证环境为 Node.js v24.19.0、本机回环 HTTP 和独立内存 SQLite。所有请求均使用测试主体，第三方身份和公众号断言由现有测试注入本地响应。

## 修改与数据流

| 文件 | 变更 |
| --- | --- |
| `shared/core.cjs` | 普通 FAQ 咨询由发起主体保留，转人工后进入客服队列。客服可查看待接单及本人负责记录，管理层可查看已升级记录。提交者收到进度及公开回复，内部协作备注保留在工作人员投影。客服网点目录返回 ID、名称、营业状态和行政区划。加盟商和区域运营的结算只返回授权报表 ID 与结算状态信息。 |
| `server/repository.cjs` | 客服与管理层的记录授权在 SQL 分页前执行。客服网点搜索使用名称、行政区划与 ID，主体筛选受限。加盟商和区域运营仅计数包含本主体或授权网点报表的结算记录，详情和列表一致。 |
| `tests/acceptance-permissions.test.cjs` | 增加七条真实本地 HTTP/SQLite 验收，覆盖咨询转人工、投诉脱敏和升级处理、客服目录及搜索、结算授权、私有定位资料及位置历史、换绑及审计保留。 |

- 地图资料。位置变更待审时原位置不变，运营审批须等待专员核验，重复审批返回 409。专员可读取与申请关联的照片，其他加盟商、访客、区域、运营、财务均收到 403。内部位置审批生效并保留旧坐标，访客继续取得单独发布的公开坐标。
- 负责人换绑。审批后旧会话和旧口令均返回 401，新负责人重新激活后继续读同一主体的三个网点和历史报表。原申请审计与负责人变更记录可回查。既有回归还覆盖冻结、员工角色变化、激活，以及注入本地响应的短信与微信身份验证。
- 客服业务。普通咨询经主动转人工后入队，重复接单返回 409。投诉加盟商仅收到脱敏协查提醒，提交者不能读取内部协作内容，其他访客不能读取原单。管理层可处理升级工单。原单关闭后保持历史，可评价并关联新工单。
- 经营信息权限。客服默认不能读取报表、账单、支付或核验集合。仅其他加盟商有报表的结算不会占用本加盟商或区域的分页。总部管理层的集团覆盖值仍可查询。

- `node --version` 返回 `v24.19.0`。
- `node --test tests/acceptance-permissions.test.cjs` 首次执行 0 通过、4 失败，均为预期权限断言。补充目录搜索、位置变更和换绑场景后，搜索断言单独失败。最终同命令 7 通过、0 失败。
- `node --check server/repository.cjs`、`node --check shared/core.cjs`、`node --check tests/acceptance-permissions.test.cjs` 均退出 0。
- `node --test tests/acceptance-permissions.test.cjs tests/admin-security.test.cjs tests/backend.test.cjs tests/domain-remediation.test.cjs tests/operations.test.cjs tests/official-account.test.cjs tests/miniprogram-remediation.test.cjs tests/upload-security.test.cjs tests/external-auth.test.cjs` 共 90 通过、0 失败。上传回归注入 SQLite 写入失败以确认事务回滚，对应一条预期错误日志。

## 兼容性、成本与待验证项

- 结算金额、方法和统计口径沿用现有实现。本次只收窄部分角色的响应字段、结算范围、客服目录与授权操作。可用的旧记录原样保留，数据库无结构迁移。新增的是 SQLite 查询约束及响应投影，无新依赖、第三方调用费或模型费用。真实数据量下的查询性能尚待发布环境验证。
- 第三方真实身份、公众号送达、真机地图与 GPS 权限未在本轮运行。总部 Web 浏览器回归由最终 ZIP 独立验包执行。V3.1 总部细分岗位授权需集团确认，现有运营、财务和定位专员按既定岗位功能授权，个别人员网点和有效期授权已在区域岗验证。
- 公众号送达状态使用独立入口，已提交权限复核。目标边界为 `wechat` 会话、客服可查已主动转人工且处于待接单或本人负责的会话、管理层可查已升级会话。
