# 通知跳转验证报告

**本地链路已完成并验证。** 使用原生小程序 Page 桥接、真实本地 HTTP、隔离 SQLite 和模拟支付服务复核 Q04、Q10 及 Q12 相关场景。

| 通知入口 | 打开后显示 |
| --- | --- |
| 经营月报 | 通知对应的网点、月份和只读版本正文 |
| 月报更正、撤销复核 | 指定更正版本或撤销所指向的原版本，财务复核状态与月报一致 |
| 咨询服务费 | 指定账单的明细。付款通知打开该次付款，冲正通知定位原账单与更正记录，费用核算通知打开对应核算结果 |
| 退款 | 指定退款申请、对外凭证号和关联的原付款，可继续打开精确的原实收记录 |
| 网点 | 发生状态变化的网点档案 |
| 位置核验 | 对应网点、月份和历史提交，即使同一月份已有补件也保留原记录位置 |
| 客服 | 对应工单或在线咨询。从客服返回会恢复消息筛选和所打开的通知，包括分页以外的消息 |
| 业务申请 | 对应申请记录和公开处理说明，位置核验通知若关联新增或变更网点申请也打开该申请 |

## 权限、历史兼容与数据

- 通知跳转复用按当前会话授权的详情读取。消费者投诉协查提示只展示协查说明，消费者工单继续按工单所有者及客服岗位授权。标为已读和关闭业务待办仍是独立操作。
- 历史日程提醒凭已关联的任务恢复网点、月份或账单，返回给加盟商的仍是可授权业务记录。历史渠道退款只在确认时间、账单、原实收和退款申请唯一匹配时恢复详情，无匹配或多条匹配时停用详情入口。
- 月度核验的内部依据留在总部审批和审计中，单列可选的公开说明。历史消息展示核验状态对应的固定正文，申请人审批历史可见对应事件的公开说明。
- 退款双方保留原有金额、币种、账簿统计和状态口径。数据库保留渠道核对与去重引用，加盟商退款详情输出 `customerReference`。本工作包无需迁移或新增依赖。
- 打开通知产生有界的授权详情读请求。旧通知的关联查询使用现有任务主键、账单、实收及退款关系索引。此步骤无外部调用和模型费用。

## 人工复核路径

1. 在隔离环境用加盟商帐号提交月报、更正、位置核验、申请、工单和人工咨询。由有权岗位产生通知，核验时分别填写内部依据与公开说明。
2. 生成服务费账单，使用模拟付款与退款，另在总部处理一条账单更正和一条费用核算。从小程序「我的 → 消息」打开各条通知，检查指定版本、网点或原付款记录。
3. 在「未读」筛选下进入客服通知，从客服点击「返回消息」，再次打开同一通知。用另一个加盟商帐号验证无权打开原业务记录。
