# 微信 19 页模拟器逐页验证表

> 历史资料。下文的“当前”“本轮”及验收数字均指报告出具时的版本。现行范围及验收进度见[项目文档索引](README.md)。

路由及顺序来自当前 `miniprogram/app.json`。V3.3 缺陷整改复验基线因安全信任提示阻断，已通过 **0/19**。本次最终候选制包时已通过 **0/19**，逐页状态均为“未运行”。更新本次结果时，在最终 ZIP 同级的 `最终候选微信实测证据/` 保存本表的实测记录并登记 ZIP SHA256。

每页共同验收项为打开、显示、主要按钮、数据请求、返回、重新进入和无权限验证。Tab 页通过切换 Tab 后返回复测，详情页从原业务入口返回并重进。用访客和另一隔离加盟商复核受限状态，记录预期的入口隐藏、页面提示或 HTTP 权限错误。公开页应检查其仍可访问，以及看不到私有、未发布或已撤回记录。请求证据记录方法、路径、状态码和请求 ID，与脱敏截图或录屏对应。

## 三条联动流程

| 流程 | 模拟器与总部 Web 联动 | 验收记录 |
| --- | --- | --- |
| 月报提交与总部审核 | 加盟商甲选择自己可填报的网点和账期，保存草稿、退出重进、提交。总部运营在同一隔离后端查到该条月报并审核。模拟器刷新后核对有效版本、审核状态和通知跳转。 | 记录网点、账期、月报 ID、草稿/提交/审核请求 ID 与审核前后截图。验证另一加盟商无法查看。 |
| 账单与模拟支付 | 在隔离库选择有效未支付样例账单。按样例分别运行模拟微信、模拟支付宝，核对成功和取消/失败分别作用于独立样例。总部财务对照同一账单、支付记录和可核对状态。 | 保留账单 ID、模拟渠道与结果、金额和请求 ID。确认真实渠道均为关闭，避免已支付样例影响重复测试。 |
| 客服提交与总部处理 | 以隔离加盟商创建工单，总部客服查看、接单/处理并回复。小程序刷新或通过消息打开该工单，核对实际回复与状态。 | 保留工单 ID、提交/接单/回复请求 ID 和双端截图。核对另一加盟商不能读取。 |

一次测试批次内的模拟器和总部 Web 使用同一个进程、端口和库。若缺少样例记录，先通过本包测试数据或总部 Web 的业务入口准备合成样例，登记样例来源与角色。每页满足常规与权限项才计为通过，未进入、已失败和待解锁环节按实际分别记录。
