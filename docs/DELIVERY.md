# V3.3 整改交付与人工验证

> 历史资料。下文的“当前”“本轮”及验收数字均指报告出具时的版本。现行范围及验收进度见[项目文档索引](README.md)。

在最终交付目录核对 `九盈英才_V3.3_全量问题整改_完整源码.zip`、`SHA256文件清单.txt` 和 `重新解压验包记录.json`。校验 ZIP 摘要后解压到空目录，按 `最终测试报告.md` 核对依赖安装、迁移、测试、编译的实际退出码和 `验包日志_<时间>/` 中的原始日志。以上路径均相对于最终交付目录。证据索引见 [V3.3 当前发布状态](V3.3当前发布状态.md)。

本轮人工复核使用独立的 SQLite 测试库、已授权测试号和开发 Mock 配置。微信模拟器须先由授权操作人核对 ZIP 的 SHA256 并按 [人工解锁步骤](微信模拟器人工解锁步骤.md) 处理项目作者信任提示，再执行下列流程。

1. 通过 `scripts/setup-admin.ps1` 初始化空测试库，开通个人岗位与负责人测试账号。验证激活、密码登录、改密、冻结和换绑后旧会话失效。短信和微信绑定使用测试替身，核对非开发构建已移除开发角色入口。
2. 只填收入存草稿并重进恢复，验证缺项提交拒绝、招生待确认、总部设置生效期、V1 批准与 V2 待审并存、单项及整版更正、收入复核、结算覆盖率与导出审计。
3. 提交新网点照片，验证专岗核验、唯一建档和已确认基准。检查现场 GPS 与地图选点的记录标识、权限拒绝及重试。交替使用访客和加盟商账号，核对公开目录仅返回获准公开的字段和坐标、私有网点按主体授权。真机上的系统授权、定位和照片流程另行验收。
4. 用明确的测试价格及整月协议生成应收账单。在隔离库通过开发 Mock 验证预下单、成功、取消、失败、查单、线下凭证、退款与冲红。用本地签名替身验证渠道回调重放、超时关单、迟到付款、退款回查及按原单对账。复核前端支付结果仅触发查单，实收以服务端确认且只入账一次。
5. 验证客服咨询、正式工单和总部处理，使用签名替身验证公众号加密消息与回复 outbox。核对五大业务草稿、发布、撤回与独立公开图片，检查超过 200 条后的分页、XLSX/PDF 导出和隔离备份恢复。真机文件打开、正式公众号送达和运行告警在对应环境另行验收。

## 后续真实商户联调

集团提供微信与支付宝商户和应用资质，核定协议收款主体、账单快照与渠道商户映射，配置正式 HTTPS 域名与回调，并书面授权测试范围后，再按渠道方案安排真实商户联调和对账。本轮禁止启用真实商户、扣款和退款。已发生的外部资金动作须通过渠道对账与补偿处理。详见 [双渠道接口说明](微信支付与支付宝双渠道接口说明.md)。

真机、真实平台、甲方预验收与正式放行按各自环境取证。资料及未决规则见 [上线资料清单](上线资料清单.md) 和 [待确认规则](PENDING_DECISIONS.md)。
