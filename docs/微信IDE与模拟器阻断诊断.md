## 已核验的阻断与影响

| 阻断 | 可核验事实 | 下一步 |
| --- | --- | --- |
| CLI 服务端口关闭（历史基线） | 微信开发者工具 2.02.2609250 Stable 的两份日志均显示 `IDE service port disabled` 和 `工具的服务端口已关闭`。执行资料记载历史 `open` 退出码为 0，命令结果以连接错误文本和 IDE 原始状态为准。 | GUI 导入可独立进行。只有需要 CLI 且得到明确授权时，操作者才在「设置 → 安全设置 → 服务端口」启用。 |
| 项目作者信任提示（历史基线） | 历史截图可见 IDE 已打开小程序项目，中央提示「您信任此项目的作者吗？」，提供「稍后运行」和「信任并运行」，右侧模拟器仍显示工具欢迎页，页面路径为空。 | 操作者核验最终候选 SHA256、来源与导入路径后，在该项目窗口自行决定是否信任。 |
| 最终候选 GUI/CLI | 必须从最终 ZIP 独立解压后实际尝试并记录。制包时最终候选页数 **0/19**，未取得其交互验收证据。 | 从本次交付 ZIP 同级的 `最终候选微信实测证据/` 核查同 SHA256 记录和实际通过数。 |

安装目录中的官方 CLI 入口先读取工具自身的服务端口状态，状态未开启便输出错误并在尝试建立 IDE 连接、分发项目命令前退出。项目配置未参与该判断。CLI 的端口设置和 IDE 的项目安全信任分别控制命令连接和项目代码运行，开启服务端口不会代替信任确认。此前同时出现的 `punycode` 弃用警告不影响对上述错误的识别。

本轮 D 工作流运行了 `cli.bat --help`，退出码 0，可见 `open`、`islogin` 等命令。本次只读帮助不连接 IDE 或注册项目。历史导入日志与最终候选尝试分别归档。静态检查、预编译及现有开发构建脚本均无证据表明能通过项目改动解除上述两道工具门禁，因此维护范围为运行和验收文档。安全提示由人确认，端口设置按操作者授权独立处理。详见[人工解锁步骤](微信模拟器人工解锁步骤.md)。
