## D07 验证状态

发布、草稿隔离、原生栏目及详情、撤回、恢复、历史与附件权限已实现并通过本地联测。总部 Web 完成 Chrome 实际操作验证。微信官方 WXML/WXSS 编译覆盖 19 个页面。访客原生页面联测由 Node 执行页面逻辑并绑定本地 HTTP 和 SQLite，真机、集团正式资料及甲方验收待完成。

| 业务行为 | 验证结果 |
| --- | --- |
| 五个独立栏目 | 测试将 service-1 至 service-5 发布。原生服务列表按固定栏位显示后端标题和摘要，点击进入对应原生详情。空栏显示“正式资料待发布”。 |
| 草稿隔离 | 发布 V1 后保存 V2 草稿，公众、小程序后台角色的公开栏目都读取 V1。草稿、历史版本和草稿封面仍受权限限制。 |
| 正文和封面 | 原生详情通过只读公开集合取得发布正文，封面用微信原生下载 API 访问现有附件权限端点。测试验证下载接口返回实际图片字节。 |
| 更新和撤回 | 发布 V3 后，原生详情显示新版本。撤回生成 V4，公开详情不可读取，旧直达链接失效，栏目返回待发布，未被其他公开内容引用的封面停止公开。 |
| 恢复和追溯 | 恢复 V1 生成 V5，保留来源版本、操作者、原因及历史。恢复验证仅接受此前已发布的版本，过期管理员页面提交被版本校验拒绝。 |
| 附件权限 | 加盟商上传的私有现场资料不能作为公开封面。恢复历史版本时重新验证封面仍为总部独立上传的合格素材。已有文件与历史保留。 |

## 实现与人工复验

总部管理层在「公开内容维护」选择业务 1 至 5，录入实际获准公开的标题、摘要、正文和封面，选择「保存草稿」或「发布为公开信息」。小程序以访客身份进入「集团与服务」→「服务业务」，依次核对栏目和详情。在总部「发布管理」撤回任一栏目，然后用原生详情旧链接及封面地址验证权限撤回。选定已发布的历史版本和恢复原因后，再核对公开详情与总部版本记录。

发布操作继续使用现有 SQLite 内容及版本表，无 D07 数据库迁移。对外用 `/api/collections/publicContents` 和 `/api/collections/publicContents/{id}` 读取公开投影，管理端保留编辑和历史集合。其余公开栏目复用同一公开投影。原生列表最多对应五张业务封面的下载，详情最多下载当前一张封面。集团正式栏目命名、发布顺序、图片权属和素材确认仍需集团提供。

## D06 公众号出站复验

客服在总部会话中接单并提交内部升级原因。管理层可以只填写内部处理结论，也可以另填用户可见回复。内部处理及协作内容留在授权的总部记录。由已登记公众号联系人发起的会话，其显式用户回复随业务记录在同一事务进入队列。

本地 HTTP 测试复现旧版内部结论进入聊天正文、管理层回复出站缺失，再验证岗位权限、幂等、48 小时回复窗口下的有限重试、平台接受返回码和模拟状态。明确的可恢复拒绝最多尝试三次。发送后无法确认结果时保留待核实状态。无正式凭证的开发 Mock 标记为“已模拟发送”。Chromium 界面和注入运输适配验证已完成，真实公众号送达、用户阅读及甲方验收待完成。

迁移 019 为出站记录追加渠道模式、平台返回码、平台接受时间和下次尝试时间，并为待发送队列增加索引。旧库升级并重启后，既有出站记录保留且 SQLite 完整性检查通过。Mock 队列和正式发送队列分开处理。证据为 `V33-D06-red.txt`、`V33-D06-migration-retry.txt`、`V33-D06-D07-node.txt`、`V33-D06-D07-browser.txt` 和 `V33-D06-HQ-delivery.png`。
