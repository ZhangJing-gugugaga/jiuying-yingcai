## 接口契约

- `GET /api/collections/outlets?scope=public` 和 `GET /api/collections/outlets/{id}?scope=public` 使用同一公开目录。支持当前登录和访客会话。列表支持 `limit`（1–200）、`offset`、`q`、`status`、`province`、`city`、`district`，搜索公开展示字段。条目提供 `id`、`outlet`、公开档案的 `name` 和 `address`、省市区及营业 `status`，只在存在已授权 GCJ-02 坐标时提供 `publicLocation` 和兼容字段 `publicCoords`。未发布或已关闭网点详情返回 404。生产访客不传 `scope` 同样按已发布档案读取。开发访客旧接口仍支持查询示范网点标签，未发布档案时地址为空。
- 加盟商 `GET /api/collections/outlets?includeSummary=true` 按现有授权分页返回 `summary`。`period` 为上海业务当前月。`report.month` 为本月报送的上一个已结束自然月，`report.status` 汇总版本和免报事实，`report.settlementStatus` 分为 `settled`、`unsettled`、`not_applicable`。`location` 和 `fee` 各自提供当前 `month` 与 `status`。位置读取当期最新核验，账单优先在用账单，只有无替换账单时返回单独的 `reversed` 状态。缺失记录使用 `missing`。公开投影省略整份摘要。
- 加盟商退款集合及 `/api/finance/bills/{id}` 的退款区仅在已批准且原渠道单正在处理中时增加 `channelRefundStatus: 'pending'`。最终登记仍以 `status: 'recorded'` 为准，`refundRecordSource` 的 `channel`、`manual` 和 `simulation` 分别表示渠道确认、人工登记凭证和隔离模拟。结算金额、原支付单、角色权限和正式渠道回查规则沿用原有契约。
- HTTP 运行时先检查数据库的环境标记。生产标记的库交由生产运行时，带明确 Mock、沙箱、测试或模拟账务标记的库无法启动生产服务。库中原有交易保留，门禁可在隔离副本检查。缺少可信环境标记的旧记录仍需上线前核对账务来源。

## 人工复验与后续工作

1. 在隔离库由运营发布一个有公开地址的网点及一个未授权坐标的网点。以访客和加盟商分别搜索与打开详情，查看同一公开结果，再切换到「我的网点」核对权限、月报报送月、位置核验月及账期。
2. 提交月报 V1/V2，新增月报更正并重新结算。核对运营、财务和加盟商待办、审批历史、已读消息和统计导出。对隔离签名夹具发起已审批退款，核对待办理到凭证登记的状态变化和账簿金额。
3. 依次发布及撤回五项隔离测试素材，再恢复历史版本。验证旧附件权限和只读投影。由客服升级工单，分别填内部意见和公开回复，核对消息历史及本地出站状态。
4. 上线工作包括集团确认计费、转让欠款、定位逾期和 SLA 等制度，准备公开档案和正式内容，用目标数据副本执行迁移、备份恢复和容量验证，取得平台/商户资料后进行授权联调与真机验收。正式验证前持续使用独立测试库。
