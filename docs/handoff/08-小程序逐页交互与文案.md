## 1. 开发时先核对的共同规则

- 访客底栏为「首页、网点、我的」。加盟商底栏为「工作台、网点、月报、我的」。我的事项通过工作台等入口访问。Tab 页经统一跳转函数带入筛选，链接中的私有网点、月份和记录由对应页面与服务端重新确认。 [导航定义](../../miniprogram/utils/navigation.js)
- 涉及提交的页面应先让用户确认当前网点、月份或原单，再呈现能执行的主要动作。历史、详情说明及次级动作放在能主动打开的位置。网点名称、日期、金额和状态应有稳定位置。
- 长网点名、长地址及退回原因要自然换行。窄屏优先将双列切为单列。按钮保留足够点击高度，主要操作、常用入口和次级文字链接按需分组。不要用缩小字体处理排版冲突。
- 加载、空结果、失败、权限失效和提交结果未知需要不同的提示。保存失败或弱网时保留用户已填内容，写入结果以服务端为准。切账号后按新主体重查。
- 业务文案用「本月未报」「待财务复核」「提交给总部」等能直接行动的术语。保留用户所需的信息，审批人内部备注、原始状态码和接口错误细节作为内部排障资料。定位、附件和支付回执须在当前对象权限下呈现。

## 2. 20 个原生页面开发对照

路由栏链接到可编辑的页面目录。建议按表中使用场景在微信开发者工具复验真实布局。关键跨角色步骤见 [跨端办理与排错](09-跨端办理与排错.md)。

| --- | --- | --- | --- |
| [首页／工作台 `home`](../../miniprogram/pages/home/) | 公众从小程序首页进入。加盟商登录后进入工作台，也可以查看公众页再返回 | 公众先看到集团与网点入口，登录及联系总部可见。加盟商先看真实待办和明确的下一步，再看服务费/核验/事项和经营概况。建议把未读数作为通知入口的一部分 | 同一小程序分别用访客、已登录加盟商和无网点账号打开。首屏读得到身份、主操作、空态；长负责人名和多条待办自然换行 |
| [登录 `login`](../../miniprogram/pages/login/) | 访客主动登录，或访问需授权页面后跳转 | 按配置显示密码、微信、短信入口。输入视图保留明确标签和错误位置，激活和登录分别说明。登录成功恢复受支持的目标 | 从月报或原单链接触发登录，回来仍是同一网点/月/单。渠道未开通时界面不会引导不可执行操作。弱网失败可重试 |
| [网点目录 `outlets`](../../miniprogram/pages/outlets/) | 底栏网点，首页的查找服务网点和全域地图 | 访客看已发布网点，加盟商可进入本人网点。地图、列表、区域和搜索有清晰的当前范围。底图失败时可直接查同范围地址 | 切国内外、区域、地图和列表，确认选项与地址匹配。长店名、无结果、多页网点不混入其他主体私有档案 |
| [网点详情 `outlet`](../../miniprogram/pages/outlet/) | 网点列表或地图点，使用 `id` 和公开/私有范围链接 | 首屏先给名称、营业状态和地址。公开资料按发布范围返回，私有办理项按主体展示。长地址采用纵向布局 | 验证境外地址和公开资料缺失时的反馈，访客与加盟商查看同一网点的不同权限，关闭/撤回后旧链接的表现 |
| [月报列表 `reports`](../../miniprogram/pages/reports/) | 加盟商月报 Tab、工作台或通知跳转 | 展示报送月份与选中的网点范围，优先显示待报、退回等需要动作的状态。空状态解释当前筛选 | 用三个网点跨两个月筛选，检查当前有效版与最新提交状态。掉线后恢复仍是原范围，点击行打开正确月份 |
| [月报详情／编辑 `report`](../../miniprogram/pages/report/) | 月报列表、待办或带 `outlet`、`month`、记录 ID 的通知 | 建议顺序为网点月份、当前状态与退回原因、可填字段、保存/提交、历史。继续填写时突出字段错误和待办动作。跨状态保留真实版本 | 草稿、首次提交、退回重提、已通过历史、待财务复核各走一遍。切换对象、弱网、键盘、安全区和退回原因可见性均要验 |
| [服务费 `fees`](../../miniprogram/pages/fees/) | 工作台服务费、网点、账单通知 | 显示当前范围、待付金额和账单状态。筛选与历史放在独立的次级入口。原账单详情再显示付款选项 | 多网点与跨月筛选，打开账单、返回保持筛选。Mock 明确标注。重复或回执未确认时保留原账单入口 |
| [办理事项 `requests`](../../miniprogram/pages/requests/) | 网点和账号的具体申请入口，或原申请通知 | 先选事项类型，再选适用网点或保留原单锁定网点。详情优先显示当前结果、下一步和可公开意见。自然月停费与状态变更分别说明 | 新增、暂停、恢复、地址变更和账号变更查对应路径。验证原单补件、切店确认、错配和权限拒绝 |
| [网点位置核验 `location`](../../miniprogram/pages/location/) | 工作台、我的事项、网点或核验通知 | 首屏显示网点、月份和核验状态，明确下一步是采集定位、上传证据或补件。恢复地址说明后提示重新采集 | 系统拒绝定位、返回、选点、照片失败和重新上传分别验证。丢失焦点再恢复同网点月的文字，不复用 GPS 或照片 |
| [联系总部 `support`](../../miniprogram/pages/support/) | 公众首页/我的，加盟商我的/工作台，原工单通知 | 「咨询」和「提交正式工单」分别进入对应视图。已有会话/工单优先回原单。草稿恢复明确对象和附件权限 | 普通咨询、主动转人工、工单、附件、待补件、关联新工单、关闭评价。模拟响应丢失后，重试只产生一个工单 |
| [通知兼容入口 `messages`](../../miniprogram/pages/messages/) | 旧通知路径、原历史链接 | 沿用现有通知视图与兼容路由。读状态与办理状态分别展示 | 打开旧链接、点击原记录及返回。读通知后仍保留待处理事项 |
| [我的 `profile`](../../miniprogram/pages/profile/) | 底栏「我的」 | 访客可找到登录及公开服务，加盟商可见账号资料、登录安全及事项快捷入口。按角色安排主操作 | 切换两个角色，退出、再次登录后旧主体信息消失。无默认号码或外部服务时反馈清晰 |
| [付款与凭证 `finance`](../../miniprogram/pages/finance/) | 原账单、付款/凭证历史、相关通知 | 优先说明所属账单/实收、金额和状态。登记线下凭证、申请退款或发票只在允许情形显示。证据和原单可回查 | 原账单和流水返回一致；核验线下、退款审批及完成、票据状态、空凭证、错误凭证和重复操作 |
| [我的事项 `tasks`](../../miniprogram/pages/tasks/) | 工作台待处理/未读入口，或者「我的」 | 待我处理、处理中、通知及已完成记录标明各自状态。每项例示下一步，已结束的单据给查看原单 | 从通知进入再返回；单独打开已完成事项时高亮对应状态。当前源码将已完成高亮到「通知」，列入待修 |
| [集团介绍与服务 `discover`](../../miniprogram/pages/discover/) | 公众首页、集团介绍、业务及合作入口 | 按已发布栏目展示，常见问题、合作说明和公司业务分开。合作留言清楚说明联系资料用途和提交状态 | 切栏目，检查长正文与空栏目。合作同意、提交、撤回公开内容后刷新，保证原处理进度仍能查看 |
| [业务详情 `service-detail`](../../miniprogram/pages/service-detail/) | 首页集团业务卡片或集团页，带发布项 `id` | 首屏显示业务名称和发布正文，图片预览有失败提示。回入口应保持适当位置 | 已发布、未发布/撤回、图片加载失败、长标题/正文、正常返回 |

| [账号安全 `security`](../../miniprogram/pages/security/) | 加盟商「我的」 | 显示绑定方式、改密与负责人或手机号变更入口。变更提示解释需要重新激活的情形 | 测试密码更新和会话失效，验证变更申请返回原单与未配置外部渠道时的反馈 |

文案建议样例

| 场景 | 建议表达 |
| --- | --- |
| 月报被退回 | 「月报退回 · 10 月」「请核对有效订单」「修改后提交」 |
| 月度定位证据不足 | 「还需要现场定位」「去定位」，照片未上传时单独指出照片 |

| 授权已失效 | 「你暂时无法查看这条记录」「返回我的事项」 |
| 当前没有数据 | 写明当前网点、月份或筛选条件，并提供返回或调整范围的操作 |
