# 九盈英才 V4.1 完整需求与功能设计

## 1. 定位和范围

九盈英才统一服务集团的公开展示、加盟商网点运营协作及总部管理。公众用小程序发现服务，加盟商用小程序或受限 Web 办理网点事项，总部在 Web 审批、发布、处理客服和结算。双方使用同一业务记录与接口。三方的操作权限见 [三方关系与权限明细](02-三方关系与权限明细.md)。

现行范围以 V4.1 源码行为和一期范围收敛为准。历史需求讨论基线保留业务背景和集团待定事项。独立 APP、独立支付宝小程序、新抽佣模式按现行范围保留在候选库。既有培训记录保留与原业务连通，独立一期培训范围待集团确认。 [历史需求基线](历史需求依据/02_当前有效需求基线.md) · [一期范围收缩执行包](../../docs/superpowers/plans/2026-11-20-phase-one-scope.md)

## 3. 关键业务与状态规则

### 3.1 账号、网点和公开信息

1. 总部创建加盟主体及唯一负责人账号，签发一次性激活码。负责人可管理本主体多个网点。总部人员使用个人账号与岗位授权，微信或短信入口取决于服务器配置。
2. 账号冻结、停用和负责人或登记手机号变更由授权岗位处理。身份变更核对绑定版本，旧会话和旧认证撤销，新负责人重新激活。同一主体的网点及历史保留。
3. 新增网点由加盟商填基本资料、地址及位置证据。专岗核验后运营或管理层审批，通过时创建一个筹备中网点。总部记录开业、暂停或关闭等有效日期和原因。关闭网点历史保留，公众目录按可公开状态展示。
4. 公众只读已发布内容和允许披露的网点字段。公开坐标与私有实际经营位置分开。公开地图不能加载时，仍可打开同范围的地址列表。内部位置变更审批和公众发布分别记录。
5. 历史转让、重新开店后的欠费和访问归属需要集团制定制度。批量导入先预览，审阅校验结果后提交。

### 3.2 月报、修订与统计

1. 按网点和上海时区自然月填报。四项指标为营业收入、有效完成订单、到店客流和实际招生，经营说明选填。缺失、不适用、实际零值和整月暂停免报分别表达。招生适用性待确认时，先由授权岗位处理，再提交正式月报。
2. 草稿可部分填写并回读。提交创建版本，待审版本锁定。同一对象不接受重复在审版本。逾期可补报，截止及节假日按已生效制度执行。整月暂停经确认可免报，月中暂停仍报实际经营。
3. 普通月报由运营或已有该网点审核授权的区域运营处理，管理层也具备相应审批能力。退回须写理由，加盟商从原单重提生成新版本。此前通过的有效版继续保留，直至合规的新版本通过或撤销正式生效。
4. 已批准记录可由加盟商发起单字段或整份更正。历史收入变化须转财务复核。误审批撤销由管理层发起、财务执行现有复核流程，正式独立复核制度待集团确认。
5. 过程统计读取当前有效审核数据。正式统计由管理层按已结束自然月结算，记录所纳入的版本和覆盖范围。已结算期发生更正或撤销，旧快照失效并进入重结算。汇总层调整留前后值及依据，收入调整经财务，原始月报版本保留。
6. 统计以实际覆盖范围计算，禁止以当前分页加总集团数据。基础字段和方法须可追溯。同比、环比遇基期为 0、缺月或不可比时明确提示。集团排名是分别按四项展示，管理层可见。加盟商导出限本主体网点。历史要求至少保留五年，实际备份保留和恢复制度需集团落实。 [统计原始要求](历史需求依据/06_经营数据看板与统计规则.md)

### 3.3 月度核验、位置变更与申请

1. 核验提醒指向本主体正确网点和月份。负责人主动获取现场 GPS、补充实际地址和上传现场照片。手动选点可协助说明地址，月度现场通过要求 GPS。审批人员按已确认基准、坐标系和精度核查，异常先解释和补件。
2. 位置核验草稿仅恢复同会话、同网点月份和同总部记录状态下的地址及说明。继续办理需重新采集位置证据。更换账号、记录失效或成功交付后不再恢复该草稿。
3. 新增、地址变更和月度现场核验是不同记录。地址变更待审时旧地址仍有效，审批通过后内部位置留历史，公众坐标经独立发布。补件如果实质修改坐标、地址或照片，重新核验。
4. 已绑定网点的申请在同一网点继续。新增网点可在主体下提交无既有网点的申请。申请状态为待审、待补充、退回或通过。公开处理说明供申请人查看，内部审核意见按岗位权限投影。
5. 位置截止/豁免、异常阈值、照片留存和特殊证明由集团落实成显式制度。

### 3.4 服务费、付款与财务复核

| 阶段 | 业务规则 |
| --- | --- |
| 价格与协议 | 以确定生效的价格版本和网点协议写入快照，保留服务主体、收款主体、开票主体。按确认的整月计费期间和出账/截止规则生成应收；例外首月、分摊和转让待制度。 |
| 账单与支付 | 当期唯一有效账单。支付订单（可能有多次尝试）与应收、实收各自存在。渠道成功须由服务端验签/查单且校验订单、金额和商户后写入一次实收。客户端回执仅触发核验。失败或取消按渠道事实处理。 |
| 线下凭证 | 当前入口要求和账单等额的全额收款。保存付款日期、金额、外部流水与依据，由独立财务复核完成入账；已存在实收或在途在线支付时先核对。 |
| 暂停收费与抵扣 | 营业暂停和收费暂停分别申请。停费批准先形成金额未知的待核算记录。运营或管理提出金额、抵扣年月及明确的服务期顺延参数，独立财务复核后应用。抵扣月份已有账单先处理账单纠错。 |
| 退款 | 关联原实收，按未被既有退款申请占用的可退余额校验。申请、批准、外部执行或渠道核实、退款凭证记账分别留痕；渠道待核实保持处理中。已开票的退款与票据按状态规则协调。 |
| 发票与冲正 | 发票申请、开具、拒绝/取消和红冲状态分别展示，留票号日期。错账经独立复核冲正旧单并生成替代记录，保留原凭证及审计。 |
| 金额与汇总 | 金额以整数分运算及持久化投影，展示时格式化为元。未知金额为 null。应收、实收、退款、净实收、未收与逾期有独立字段。财务汇总基于完整授权范围。 |

本地隔离配置允许 Mock。微信和支付宝渠道边界已有适配及协议测试，真实资金、真机支付和税务需分别确认授权与联调。现有支付宝手机网站链路和历史记录可按渠道条件使用，微信原生正式支付路径按可用的微信能力展示。 [双渠道接口说明](../../docs/微信支付与支付宝双渠道接口说明.md)

### 3.5 待办、客服和内容

1. 「我的事项」承接实际业务待办，通知已读只更新通知。具体动作应从原月报、账单、申请、核验、工单或培训记录进入。业务完成、新版本替代或真实核销后才可闭合相应事项。
2. 普通咨询匹配 FAQ，用户主动选择转人工。投诉、售后和异常可单独提交正式工单，提交时确认关联对象。正式工单进入总部队列，由当前客服经办。可公开的回复和内部协作分开，严重投诉按制度升级至管理层。仅已完成人工服务可评价一次，未解决可建关联新工单。
3. 公众投诉如涉及加盟商，加盟商收到脱敏协查信息。加盟商只查看本人咨询、工单和获准的服务电话。工单草稿限本会话本机按权限恢复，发送结果未知时沿用同一请求键，避免重复建立记录。
4. 集团内容经过草稿和发布。撤回及时反映在公众列表、详情或附件鉴权中。对外联系人、图片和地图字段需有发布授权。合作留言保留同意版本和处理记录。培训的既有业务经原入口和通知继续办理，私有材料按本人/授权岗位隔离。

## 4. 共用约束和验收

- 业务查询以会话、主体、对象、岗位及有效授权联合判断。列表与详情、附件、导出、深链采用同样的服务端边界。
- 所有需要重试的业务写入使用对应请求键和服务端事务。保存了记录却没收到响应时，应能通过原单复查或安全重试。
- 后台作业使用上海时区及已生效配置。状态更新、分派交接、财务变化、发布/撤回及关键审批可回查操作人和请求号。
- 生产账号、业务库、平台密钥由集团受控配置。测试环境使用明确的隔离账号、模拟渠道和独立库。
- 验收时记录源码版本、角色、环境、操作前后状态、请求编号或截图。 [测试与开发协作](05-验收与开发协作.md) · [待确认和改进项](04-已知问题与后续改进.md)
