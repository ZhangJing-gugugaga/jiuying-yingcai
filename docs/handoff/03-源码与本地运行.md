# 源码与本地运行

本仓库的[项目根目录](../../) 是完整可编辑工程，内有源文件、版本化迁移、测试、文档、字体及许可证。历史交接基线为 V4.1 提交 `bdc8e8b58864de7de4ade8494f25603ca0d29c6e`。通过[交付完整性](07-交付完整性.md)核对原快照。当前开发基线为 V3.4.4 四入口源码，启动与版本要求见[项目 README](../../README.md)。

可按 [GitHub 接手步骤](09-跨端办理与排错.md) 克隆本仓库 main 分支。逐页修改位置见 [小程序逐页交互与文案](08-小程序逐页交互与文案.md)。

## 1. 启动隔离开发环境

安装 Node.js `>=24.19.0 <25`、npm 和适用版本的微信开发者工具。运行总部浏览器用例还需本机已安装 Chrome。以下命令在仓库根目录（含 package.json）执行。第一次生成本地配置，已有配置先检查其数据库路径及渠道模式。

```powershell
node --version
npm ci
Copy-Item .env.example .env
powershell -NoProfile -File .\start.ps1
```

默认总部 Web 为 `http://127.0.0.1:8787/`，健康检查为 `/health`，样本数据库 `var/local.db`。本地开发样本可用开发角色进入。隔离联调为每位开发者分配独立 `DB_PATH` 和空闲端口。保留 `HOST=127.0.0.1`、`ADAPTER_MODE=mock`。要避免后台定时任务干扰现场测试时，将 `SCHEDULER_ENABLED` 设为 0。启动脚本读取 `.env`。单独运行 `npm start` 或 `npm run migrate` 时，通过进程环境传入所需参数。

需要使用个人登录验证激活、交接和撤权时，走受控初始化与总部发码流程。历史账务、真实账号与密钥由集团环境管理。 [部署文档](../../docs/DEPLOYMENT.md)

## 2. 微信开发与构建

```powershell
node scripts/wechat-validate.cjs
node scripts/wechat-build.cjs --environment development --target simulator --out dist/wechat-development
```

使用已有授权测试 AppID 时，在构建前通过 `WECHAT_APP_ID` 传入。API 使用 `--api-base http://127.0.0.1:8787` 或相同的受控环境变量，对应实际本地端口。输出路径使用全新或空目录。微信开发者工具导入生成目录，启动方核对项目路径及信任提示。随后先用访客打开主页，再用隔离加盟商账号核对 `requestId`、网点权属及后端日志。 [原生工程说明](../../miniprogram/README.md)

真机测试或生产构建使用授权 AppID 和实际 HTTPS 测试/正式 API 域名，分别选择 `--environment test` 或 `--environment production`，并指定 `--target device`。非开发构建会剥离开发身份、Mock 交互与本机开发诊断。AppSecret 等平台凭证通过服务端配置。 [上线资料](../../docs/上线资料清单.md)

## 4. 注册页面和入口

访客自定义底栏显示首页、网点、我的。加盟商显示工作台、网点、月报、我的。客服由「联系总部」入口打开。「我的事项」承接待办和通知。旧路径仍用于兼容历史消息。

| 主包路由尾段 | 用途 |
| --- | --- |
| `home` | 公众首页、加盟商工作台、当前待办和经营摘要 |
| `login` | 登录与首次激活 |
| `outlets`、`outlet` | 公开目录、我的网点、网点详情及地址 |
| `reports`、`report` | 月报列表、填写、草稿、历史与更正 |
| `fees`、`finance` | 账单与缴费、历史及线下凭证、退款、票据 |
| `requests`、`location` | 业务申请原单、位置核验与历史 |
| `support` | 联系总部、普通咨询及正式工单 |
| `tasks`、`messages` | 我的事项、通知兼容入口及原对象跳转 |
| `profile` | 我的账户及相关业务入口 |
| `discover`、`service-detail` | 集团栏目与已发布业务详情 |
| **分包路由尾段** | **用途** |
| `dashboard` | 经营看板与授权导出 |
| `agreements` | 服务协议及历史 |
| `security` | 账号安全、绑定状态及账号变更 |
| `training` | 既有培训业务与历史的受限入口 |

全部实际路由为 `pages/<尾段>/index`。 [路由注册源码](../../miniprogram/app.json)

## 5. 接口、数据、变更约束

| 入口 | 契约要点 |
| --- | --- |
| `GET /api/config`、`/api/context` | 环境与可用渠道、角色、当前主体、授权和业务日期。配置决定前端入口 |
| `/api/auth/*` | 密码、激活、访客、微信、短信、账号安全及适用总部身份能力。服务端签发会话并核对状态、有效期和绑定版本 |
| `GET /api/collections/:name[/:id]` | 按授权过滤后分页，默认 50、最大 200；详情与列表按同一边界。组合筛选以实际字段契约为准 |
| `POST /api/commands` | JSON `{command, payload}`，带 `Idempotency-Key`。同主体同键的相同请求可复核前次处理，修改负载应使用新键 |
| `/api/tasks*`、`/api/reports/context` | 事项概览/列表/详情，报送资格、网点月份、状态及最近版本 |
| `/api/dashboard`、`/api/export`、`/api/finance/*` | 统计过程/正式层、授权导出、服务费汇总及台账 |
| `/api/files`、`/api/files/:id` | 图片上传/受权限保护的读取。附件用途、尺寸、图像解析及提交归属由后端校验 |
| `/api/work-contacts*`、`/api/approval-exports*`、`/api/training/*` | 授权工作号码、按字段导出管理与下载、既有培训业务 |
| `/api/payments/*`、`/api/wechat/official/*` | 在线支付、渠道查询和证据、公众号入站与回复。需受控渠道配置 |

正常 JSON 响应包含业务数据和请求编号。业务命令按当前对象状态处理，外部调用保持有限超时和重试。改动接口前核对小程序、总部 Web、相关脚本和测试；保留旧数据读取，结构变化使用新增的前向迁移。影响资金、结算、权限或历史数据时使用目标库的脱敏副本验证，带对账和回退步骤。 [API 契约](../../docs/API.md) · [数据字典](../../docs/DATA_DICTIONARY.md) · [服务端路由](../../server/index.cjs)
