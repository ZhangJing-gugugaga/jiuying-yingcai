# 全渠道客服机制需求

## 客服定位

全渠道客服由总部统一管理，服务对象包括加盟商与终端消费者。客服是正式产品模块，不是简单的“联系我们”页面。

## 渠道

- 消费者：微信公众号、小程序。
- 加盟商：小程序在线客服、电话客服。
- 官网客服入口尚未确认，不自动增加。
- 常见问题自动回复＋人工客服；用户可自主选择是否转人工。
- 当前不引入AI客服，除非后续明确决定。

## 普通咨询和工单

- 普通咨询：保留聊天记录，不自动生成正式工单。
- 投诉、售后、业务异常：生成正式工单。
- 所有工单进入统一队列，由客服人员自行接单。
- 总部客服始终负责整个工单；需要时可联系加盟商或内部部门协助，但不转移工单负责人。
- 客服标记完成即可关闭，用户可以查看历史记录。
- 工单关闭后仍未解决，用户重新提交新工单，并关联原工单。

## 处理与升级

- 消费者投诉由总部客服直接处理。
- 所有消费者投诉都通知对应加盟商。
- 严重投诉由总部高级管理人员处理。
- 只评价人工客服服务质量。
- 总部自行设置客服服务时间。
- 首次响应时限按工单类型配置，具体时限数值待定。
- 客服不能直接修改账单、月报、网点状态或费用；相关事项必须走正式业务申请/审批。

## 权限与隐私

- 客服默认不能查看加盟商经营和财务数据；确有需要时由总部授权。
- 消费者投诉通知加盟商时，只共享处理所需信息，避免不必要披露消费者个人资料。
- 工单中涉及的网点、账单、报表关联应有权限校验。
- 电话客服可由客服人员在系统中代为登记工单，但需记录来电渠道、登记人和时间；电话是否录音未确认，不得默认启用。

## 推荐的工单字段（产品设计建议）

工单编号、来源渠道、咨询者类型、咨询者身份/联系方式、所属加盟商/网点（适用时）、问题类型、标题、描述、附件、优先级、当前状态、接单客服、协助部门/人员、首次响应时间、处理记录、关闭时间、评价、关联原工单。

## 原型状态建议

普通聊天与正式工单分开展示。工单状态可以采用“待接单、处理中、待补充、已完成/已关闭”，但状态名和升级规则如未确认，应标记为原型建议。统一队列中客服可点击“接单”；接单后当前负责人为总部客服；内部协助只增加协作记录。
