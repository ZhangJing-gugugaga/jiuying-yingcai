# 微信模拟器人工解锁步骤

> 历史资料。下文的“当前”“本轮”及验收数字均指报告出具时的版本。现行范围及验收进度见[项目文档索引](README.md)。

## 准备同一最终候选及隔离后端

1. 从本次交付目录取得最终源码 ZIP 和对应版本索引，执行 `Get-FileHash -Algorithm SHA256 -LiteralPath <ZIP文件>`。与交付 SHA256 完全一致后解压到新目录，使用其中的 `jiuying-yingcai` 根目录。登记 ZIP SHA256、运行时间、解压源码路径和工具版本。运行日志、截图与逐页记录放在最终 ZIP 同级的 `最终候选微信实测证据/`，对照[实际验证报告](微信模拟器实际验证报告.md)。
2. 在 Windows PowerShell 中进入解压后的源码根目录，确认 `node --version` 符合 `package.json` 中的版本范围。执行 `npm ci` 和 `node scripts/wechat-validate.cjs`。需要再次采集官方编译证据时，执行 `node scripts/wechat-compile.cjs --tool-dir <本机已核验的官方安装目录> --project miniprogram --out execution/wechat-final-official`。官方报告只覆盖 WXML/WXSS。
3. 在同一源码根目录运行下列命令。先确认 18886 未被占用，若改用其他未占用端口，同时修改构建参数、总部 Web 地址与健康检查地址。迁移和服务器都读取本次专用 SQLite，子进程采用显式开发环境，真实平台能力关闭。以下 `Resolve-Path` 路径替换为实际交付证据目录。

```powershell
$evidence = (Resolve-Path -LiteralPath '<交付目录>/最终候选微信实测证据').Path
$runId = [Guid]::NewGuid().ToString('N')
$port = 18886
$working = (Get-Location).Path
$runDir = (New-Item -ItemType Directory -Path (Join-Path $working "execution/wechat-final-$runId")).FullName
$db = Join-Path $runDir 'isolated.sqlite'
$project = Join-Path $runDir 'native'
$base = "http://127.0.0.1:$port"

node scripts/wechat-build.cjs --environment development --target simulator --app-id touristappid --api-base $base --out $project 2>&1 |
  Tee-Object -FilePath (Join-Path $evidence "build-$runId.txt")
if ($LASTEXITCODE -ne 0) { throw '微信开发构建失败' }
Get-Content -LiteralPath (Join-Path $project 'build-manifest.json') -Raw
$runner = @'
const { spawnSync } = require('node:child_process');
const [script, dbPath, port] = process.argv.slice(1);
const child = spawnSync(process.execPath, [script], {
  stdio: 'inherit',
  env: {
    SystemRoot: process.env.SystemRoot,
    NODE_ENV: 'development', HOST: '127.0.0.1', PORT: port, DB_PATH: dbPath,
    ADAPTER_MODE: 'mock', WECHAT_AUTH_MODE: 'disabled', SMS_PROVIDER: 'mock',
    WECHAT_PAY_ENABLED: '0', ALIPAY_ENABLED: '0', WECHAT_OFFICIAL_ENABLED: '0',
    SCHEDULER_ENABLED: '0', REQUEST_LOG: '1'
  }
});
if (child.error) throw child.error;
process.exitCode = child.status ?? 1;
'@

node -e $runner ./database/migrate.cjs $db $port 2>&1 |
  Tee-Object -FilePath (Join-Path $evidence "migration-$runId.txt")
if ($LASTEXITCODE -ne 0) { throw '隔离数据库迁移失败' }
node -e $runner ./server/index.cjs $db $port 2>&1 |
  Tee-Object -FilePath (Join-Path $evidence "backend-$runId.txt")
```

4. 保持后端终端运行。在另一个窗口访问 `http://127.0.0.1:18886/health` 和 `http://127.0.0.1:18886/api/config`，保存 HTTP 状态和脱敏 JSON。核对 SQLite、`adapterMode:mock`、`productionReady:false`、`devLoginEnabled:true`、`wechatLoginEnabled:false`。支付渠道应为 `wechat:false`、`alipay:false`、`mock:true`。本地测试短信的 `authCapabilities.mode` 为 `mock`，所以 `smsLoginEnabled` 为 `true`，验证码只在隔离环境生成。记录两个响应的请求 ID、隔离库标识与构建目录。总部 Web 后续打开同一根地址。

## 在 IDE 中核验和确认项目

1. 打开已核验的微信开发者工具，记录实际版本。进入小程序「导入项目」，项目目录选择上一步生成的 `native` 目录，也就是直接包含 `app.json`、`project.config.json` 和 `build-manifest.json` 的目录。使用开发构建自带的 `touristappid`（本地项目测试）。若工具要求当前操作者验证 IDE 身份，由操作者按官方流程处理并记录结果。本轮使用本地开发身份和访客。
2. 导入后若出现「您信任此项目的作者吗？」，先保存含提示、工具版本及页面路径的原始截图。在核对项目来源、ZIP SHA256、解压/构建路径并自行确认信任后，由操作者在当前 IDE 窗口点「信任并运行」。若暂不确认，记录弹窗和空页面路径，已执行页数以实际为准。
3. 点击「编译」，记录模拟器基础库实际版本、项目页路径、原生页面截图及编译摘要。完成标记以页面真实显示为依据。若 CLI 能力确需使用且用户已经授权，由用户在「设置 → 安全设置 → 服务端口」手动启用。若仅做 GUI 验收，可保留 CLI 服务端口关闭。CLI 命令日志须带 stdout/stderr 与退出码，示例为 `cli.bat open --project <native绝对路径> --lang zh`。
4. 先使用「浏览公开网点信息」验证访客，再在开发测试区使用「加盟商甲」及「加盟商乙」验证资源权限。总部 Web 用对应的隔离总部运营、财务和客服测试角色，与小程序连接同一端口及数据库。具体操作与三条验收链路见[逐页验证表](微信19页模拟器逐页验证表.md)。如使用 IDE 编译条件复查权限，保留来自正式业务入口的访问记录，并登记用于复查的路由参数和访问结果。
5. 为每次操作保存脱敏截图或录屏、页面名、角色、结果、HTTP 方法/路径/状态及请求 ID。只发布去除账户口令、会话令牌、实际手机号、身份信息、精确位置和请求体敏感字段后的证据。保存实际通过数和阻断阶段后，在终端停止此隔离后端。真钱、真实用户数据、正式 AppID、真机、真实登录短信、公众号送达和商户平台均归正式平台验收，本轮使用隔离 Mock。
