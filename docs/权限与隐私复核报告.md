# 权限与隐私复核报告

> 历史资料。下文的“当前”“本轮”及验收数字均指报告出具时的版本。查阅 [V4.1 交接说明](handoff/00-开发交接总说明.md)了解现行范围及验收进度。

## 验证结论

D03 已通过隔离 SQLite、真实 HTTP 和 Chrome 验证。加盟商读取历史申请、审批时间轴、消息详情、旧状态接口及命令重放时，都按当前角色和资源授权返回投影。

## 投影范围

| 信息 | 开放范围 |
| --- | --- |
| 申请资料和申请人可见说明 | 加盟商本人可见按类型核准的申请字段、状态、处理说明和自己的补件材料。内部备注与公开说明分开保存。 |
| 总部内部审批意见 | 总部管理层可查。运营和位置核验专员仅在本人岗位及已授权申请类型可见相关内部意见。 |
| 财务复核备注 | 总部管理层以及有权参与对应申请复核的财务岗位可见。 |
| 原始审计及操作人 | 管理层可查看原申请轨迹及审批事件追踪。加盟商时间轴仅展示本人业务步骤及可公开的处理说明。 |
| 历史误审批撤销 | 加盟商在旧申请详情中仅看到关联月报、月份、版本与公开结论。撤销发起依据、原指标载荷、复核备注及审计轨迹按岗位内部访问。拥有下属网点也不能补件或重开总部撤销申请。 |

历史记录中无法确认公开授权的自由文本继续留存原库，按结构化状态提供申请人说明。新审批可填写独立的「申请人可见处理说明」。新旧消息均按对应申请及角色投影，读取和幂等重放使用相同规则。普通申请的退回、补件和复提入口仍按原状态开放。

## 证据及复验

- 隔离库写入带内部标记的旧备注，分别验证申请详情、列表、旧状态接口、审批历史、旧消息详情、已读重放和越权访问。旧撤销申请测试验证原始数据与财务备注隔离，返回业务状态仍可查询。 回归日志（历史附件未随包提供，原路径 `../../evidence/monthly-privacy-green.txt`）
- Chrome 走查证实管理层能同时核对内部复核备注和申请人说明，加盟商页面及时间轴只显示对外说明。 浏览器日志（历史附件未随包提供，原路径 `../../evidence/monthly-browser.txt`） · 总部截图（历史附件未随包提供，原路径 `../../evidence/monthly-browser/03-总部审批分栏.png`） · 加盟商截图（历史附件未随包提供，原路径 `../../evidence/monthly-browser/04-加盟商仅见处理说明.png`）
- 微信原生申请页面已接入同一审批历史接口，支持分页和错误重试。该报告中的浏览器截图来自总部 Web 与 Web 加盟商视图。原生真机证据另见发行验收材料。

在源码根目录复验。

node --test tests/v33-monthly-privacy.test.cjs tests/v32-approval-history.test.cjs tests/acceptance-permissions.test.cjs

人工复验可用加盟商甲提交暂停收费申请。财务填写不同的内部备注与申请人说明并退回。用管理层核对两类备注，随后换回加盟商甲查看消息、详情和时间轴。用加盟商乙访问同一记录编号应被拒绝。

## 兼容与保留

旧接口路径、历史申请编号、状态和公开业务字段继续可用。对于加盟商，旧内部意见字段由独立的申请人可见说明替代。原始审计事件未因投影升级被覆盖。权限修复没有额外付费服务或模型调用。含旧投影的历史版本回退会恢复旧暴露面，发布回退版本需保留当前投影修复。
