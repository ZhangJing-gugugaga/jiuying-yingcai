## 方案取舍

| 来源 | 核查与执行口径 |
| --- | --- |
| 01、02 | 采用按用户任务和对象组织。保留 20 个注册路由及旧 `messages` 兼容入口。保留授权历史培训记录及补件跳转，培训继续退出主导航。 |
| 03、04 | 延续已有蓝白令牌、语义文字、状态色和安全区布局。按实际复用选组件，一期不批量更换原生输入、弹窗和所有卡片。颜色与文字同时表达状态。 |
| 05、06 | 公众只展示已发布信息，成员任务入口与记录同源。客服普通咨询和正式工单、申请列表和编辑可通过同一路由的不同视图进入，业务身份和历史无需迁移。 |
| 07 | 已有幂等提交、按账号读去重、授权范围与版本绑定的月报恢复。会话失效立即收回访问，避免给所有业务开启长缓存或用无身份维度的本地草稿存工单、定位与联系人。 |
| 08 | 公开工作电话、营业时间、筛选值校验、上传 multipart 和分页集合已存在。汇总不能从当前分页求和。没有发布授权的照片与服务字段不能进入公开数据，订阅模板与发放日期需集团确认。 |
| 09 | 34 张任务卡逐项记录结论。测试使用隔离环境，不使用真实交易。官方编译、总部浏览器、真实微信界面各自留证。没有微信界面数据则保持该项待验。 |

| 任务卡 | 实施或取舍 | 重点证据 |

| 01 样式 | 复用已拆分的四个 WXSS 文件。 | 公共样式和安全区审计。 |
| 02 组件 | 复用已有公共样式、表单行为和状态映射。本轮新增角色 Tab 组件。 | 状态颜色、触控尺寸和编译。 |
| 03 状态 | 现有 `format.js` 继续提供业务标签及语义色。 | 财务、客服、审批的旧状态测试仍执行。 |
| 04 Tab | 访客首页、网点、我的。加盟商工作台、网点、月报、我的。 | 路由顺序、选中状态、访客直开月报拦截和官方组件编译。 |

| 06 错误 | 沿用允许清单和请求编号，补公开模式的失效续览。 | 显式公开读可续为访客，私有读保留重新登录入口。 |

| 09 工作台 | 首屏按逾期和期限显示最多三项可打开的真实待办。独立访问服务费、我的事项和月度核验。 | 原事项标识以及待办计数。 |
| 10 公众首页 | 已发布的集团及业务内容、找网点和总部帮助集中展示。 | 公开分享、公开联系方式和境外地址。 |
