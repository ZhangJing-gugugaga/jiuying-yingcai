# 九盈英才权限、支付与安全复核

> 历史资料。下文的“当前”“本轮”及验收数字均指报告出具时的版本。现行范围及验收进度见[项目文档索引](README.md)。

通过的本地证据覆盖账号生命周期、SQL 分页授权、资料隔离、身份映射、Webhook 签名处理和业务一致性。生产安全审批和事故恢复仍待目标环境验证。

| 边界 | 实测与修复 |
| --- | --- |
| 账号与会话 | 换绑后旧会话与口令失效，历史仍归原主体。过期请求不会覆盖新登录态。 |
| 数据读取 | 加盟商和区域按授权过滤结算数量及报表 ID，集团覆盖字段留管理层。运营和财务禁读私有 GPS 与现场照，位置专员须具备关联记录。 |
| 客服 | FAQ 自留、主动转人工、待接单及己任记录、升级管理层。内部协作记录仅出现在有权人员投影及页面。公众号送达结果执行同一会话授权。 |
| 支付 | 重试时双签名密钥加载都须成功。验签查单应答校验商户、应用、商户订单号和已提供字段。未支付或关闭状态可省略微信文档的可选金额字段。成功入账仍要求准确总额和币种，回调幂等，关单审计至多一次。到账事务同时关闭待支付与逾期待办并写完成依据。 |
| 导出 | 管理层与本人授权范围，导出审计记录周期、模式、主体及网点筛选。经营说明按结算快照取数。 |
| 依赖和 ZIP | 实际运行 `npm audit --omit=dev --json`，当次记录 0 个漏洞。包按路径排除安装器、测试 RSA、私有项目设置、业务库和密钥文件。 |

原支付定向回归首跑复现配置、合法未支付查单和待办状态三个失败。修后 `node --test tests/wechat-pay.test.cjs` 7 项通过。公众号送达权限新增断言先失败后修复，`node --test tests/official-account.test.cjs` 3 项通过。权限专项 7 项通过，组合 90 项通过。最后合并及验包结果以对应日志为准。

真实商户支付、退款、券补金额和清算对账须在授权环境核实。真实资金收款仍须按渠道交易与对账凭证核验。正式目标还需 HTTPS、密钥轮换、交易异常值运营、异地恢复和容量指标。

微信官方参考 [小程序商户订单号查询](https://pay.wechatpay.cn/doc/v3/merchant/4012791900) 及 [支付成功回调通知](https://pay.wechatpay.cn/doc/v3/merchant/4012791902)。
