# 九盈英才 V3.4.4 用户路径整改工作包

**基线** `706ca7f4fb7be506d11c5800d65fbd5f931d4554`，V3.4.3。使用现有独立工作树，原交付 ZIP 保留。

**目标** 让访客自行查网点和找到登录，让管理多个网点的负责人办对对象，让提交者能查看结果并直接处理退回或补件。

**实现范围** 微信原生页面、现有 Node 和 SQLite 接口。以实际业务状态生成用户提示，保留现有审批、结算、位置核验和授权制度。总部负责审核和结果处理，服务器继续校验账号、网点、记录及角色权限。蓝白视觉以现有设计为基础。

共享工具 `miniprogram/utils/{navigation,page,api,format}.js`、消息与待办入口归主 Agent。各工作包阶段并行，执行环境最多同时运行三名子 Agent。A、B、C、D、E 由不同子 Agent 负责。

## A 公开首页、登录与跨页入口

**问题与原因** `utils/page.js` 将无会话的首页直接重启到登录页；公众使用同样的底部导航。访客个人页缺少加盟商登录入口，短信和微信未启用时仍显示可选标签。登录成功通用返回首页，导致原办理目标丢失。

**修改范围** `miniprogram/pages/{home,login,profile}/index.*` 和 `miniprogram/app.json`。共享导航和访客会话归主 Agent。B 负责月报列表中的访客入口，E 负责公开网点和地图。

**方案** 公开首页从已有访客 API 获取最小会话，显示集团业务、服务网点、加盟商登录。访客个人页提供加盟商登录和浏览入口。首次激活单独展示，公开咨询可从登录页直达；微信和手机号登录由配置决定是否可操作。需要身份的指定入口支持一次性返回合法原路由，仍以服务端权限决定记录能否显示。消息和工作台共用现有业务跳转机制，补件优先于普通通知。公开目录提供可直接使用的地址列表，允许用户切换地图；公开首页与加盟商工作台各自强调高频动作。

**验收** 干净会话直接出现公开首页、集团业务和网点；访客从「我的」进入登录；已登记账号和激活流程正常；短信、微信未开通时仅呈现可用登录操作；从受限入口登录可回原合法页面；无权记录仍不显示，对应入口给出可继续操作的说明；境外列表在底图缺失时仍能查看地址。用 `node --test tests/v34-native-navigation.test.cjs tests/v342-public-outlet-map.test.cjs tests/external-auth.test.cjs` 做兼容验证。

## B 指定网点与月报退回

**问题与原因** `report/index.js` 找不到匹配项时回落到第一个网点。月报按版本初次呈现，退回时泛称「继续填写」。月报已有表单切换保护，但原生返回路径缺少提醒。

**修改范围** `miniprogram/pages/{report,reports}/index.*` 及独立回归。使用既有参数 `outlet`、`month`、`id`。

**方案** 有一家合法网点时可以直接带入。多网点从通用入口进入时先选择。从网点详情、任务或通知进入时保留有效的指定网点、月份、版本。月报详情以退回原因和「修改并重新提交」为首要操作，历史版本仍可读。草稿与返回复用服务端草稿和微信离开提示。

**验收** 三个网点在未选择时无法写入，错误或失权网点提示重新选择或返回。退回任务打开指定月份和网点，原有效月报仍可查看。未保存退出有提醒，成功保存后重进可恢复。运行月报编辑、原生消息和责任分派回归。

## C 培训登记、资料与补件

**问题与原因** `training/index.js` 会默认第一个网点，登记后切到列表但未打开新的学员记录。审核写入 `training_reviews` 和审计，用户需要再次找到网点和记录才知道要补件。

**修改范围** `miniprogram/pages/training/index.*`、`server/training.cjs`、现有责任类别登记和培训相关测试。目标 `training` 使用 `outlet` 和 `id`，待办类型 `training_material_returned` 由共用入口路由。

**方案** 先选择办理网点。登记成功打开返回的学员记录，立即显示资料按钮；上传预览、成功提示和历史记录对应相同的学员与课程。总部退回时以现有消息/待办机制通知对应负责人，内容不含学员个人资料，点开按照记录 ID 鉴权。回补后只完成对应的补件任务。审核通过与培训完成分别展示。

**验收** 两家网点登记不会串；重复登记、网络重试和上传失败不产生重复或错误状态；总部退回本次记录后，提醒跳转正确、原因可见、上传按钮可见；他人记录不能加载；消息已读不会完成待办；补件后恢复等待审核；看到「资料通过」时能够判断培训还在进行。用 `node --test tests/training.test.cjs` 及附加回归验证。

## D 客服、申请与账单

### 客服、分派与工作电话

**问题与原因** `support/index.js` 在普通咨询默认查询第一家网点的联系方式；人工聊天和正式工单让用户重新整理描述；进入正式工单时程序可能默认选第一家。

**修改范围** `miniprogram/pages/support/index.*` 及独立客服回归。已有工单、网点电话接口和权限按原合同；通用无网点正式工单若没有已确认规则，保留总部咨询路径。

**方案** 先区分咨询、电话、需要结果的正式处理。由用户明确选择「提交问题并跟进」后预填用户自己的内容，用户确认才创建。未指定网点时按已有总部公开联系方式显示；多网点工单先确认网点，关联旧工单使用原网点。成功后展示编号和进度，历史和补件仍可找回。

**验收** 咨询、转人工和取消表单不会新建工单；从聊天主动建立工单可审阅预填内容；选择网点前不显示其他网点工作电话；授权电话和工单网点一致；总部回复后加盟商能从消息跳到对应工单，内部备注保持权限边界。用 `node --test tests/v342-native-support.test.cjs tests/v343-work-contacts.test.cjs` 及附加回归验证。

### 账单和业务申请的连续路径

**问题与原因** 服务费和付款凭证有多个同类入口；暂停营业后的记录没有在合适位置提示另行申请暂停收费。现有规则明确两项分开审批。

**修改范围** `miniprogram/pages/{fees,finance,requests}/index.*` 及独立回归。

**方案** 费用账单优先展示待支付金额和服务端付款状态，详情统一落在原账单。退款、发票和付款记录携带原单标识。在暂停营业记录提供「另行申请暂停收费」，带入原网点；在申请查看时分清等待总部、需要补件、已处理。保留原金额算法、渠道状态、申请权限和历史数据。

**验收** 同一账单在费用页与凭证详情的金额、状态一致；从账单进入后返回能定位该记录；暂停营业后可直接进入原网点的暂停收费申请，用户取消不写入，单独提交才创建第二条记录；两条记录独立显示结果。用 `node --test tests/v342-native-fees.test.cjs tests/v33-finance.test.cjs tests/miniprogram-finance-public-copy.test.cjs` 及附加回归验证。

## E 位置核验与公开地图

**问题与原因** `location/index.js` 在没有指定网点时回落到第一家。位置核验的手动选点与现场定位并列，用户容易把提交材料理解成核验通过。公开地图仅在明确报错时显示列表操作，境外出现空白底图时地址入口不够显眼。

**修改范围** `miniprogram/pages/{location,outlets}/index.*` 及位置或地图回归。

**方案** 位置核验先确定网点，再显示月份、定位、照片、提交。指定有效网点跨页填入，明确区分现场定位与辅助选点。核验状态来自记录。境外地图显示可直接使用的地址列表入口，保留同一地区筛选与原网点详情。

**验收** 三家网点的通用入口初次等待选择。手动选点提交仍等待核验，现场 GPS 由权限和总部处理分别验证。既有记录展示需补件、已通过或等待核验的真实状态。境外地图中可切换列表并打开原地址，明确记录底图表现。

## 综合验收矩阵

| 场景 | 给操作人的任务 | 通过证据 |
| --- | --- | --- |
| 新访客 | 找一个境外网点地址，再找到加盟商登录 | 小程序正常导航；网点查询请求、地址和登录入口截图。地图缺失时能直接用列表。 |
| 三网点负责人 | 处理一条退回月报，退出重进后完成重新提交 | 只写到指定网点和月份；草稿、提交、新旧有效版本以及总部审核记录可对应。 |
| 培训负责人 | 按提醒给指定学员补交图片 | 原记录、附件版本、总部审核、待办关闭和小程序结果对应；错误账号拒绝。 |
| 客服 | 咨询、选网点、创建正式工单并收到回复 | 普通咨询仅有聊天；工单进正确队列、电话匹配，回复落到同一工单。 |
| 账单与网点 | 查某月未付金额、打开原流水，再从暂停营业记录发起暂停收费 | 金额与状态一致；暂停收费未自动创建；两种申请有各自结果。 |
| 位置 | 先核对选点反馈，再执行现场定位权限拒绝与重新授权 | 手动位置和现场定位显示有明确区别；记录归指定网点和月份。真机现场定位须留真机证据。 |

验收负责人合并并审查全部差异，重跑 `npm test`、`node scripts/wechat-validate.cjs`、相关总部浏览器回归、微信开发构建与官方编译。使用隔离账号和隔离数据库，不调用真实支付或退款。实际点验沿同一个构建和后端完成，保留截图、请求编号和对象 ID。自动化、官方编译、模拟器、真机分别记录。无人指导任务只提供上述目标；需要指路、选错对象、事后说不清结果，任务未通过。新包使用独立输出目录和校验值，保留旧包以便回退。
