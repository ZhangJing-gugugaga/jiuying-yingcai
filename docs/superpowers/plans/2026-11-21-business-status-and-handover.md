# 九盈英才申请结果与跨端交接执行计划

本轮在 `codex/jiuying-ux-rework` 工作树执行，沿用当前前端修补版和隔离测试方式。目标是让申请人和总部从同一笔记录看清审批、落实进度和下一步。

| 工作包 | 修改与验收 |
| --- | --- |
| 申请结果 | 复现规则待确认和停费申请均显示「已通过」。在 `server/repository.cjs` 为授权的申请列表、详情增加业务进度。停费从关联调整记录与待审提案取状态，抵扣入账后关联原月份账单。保留现有审批枚举、筛选和审计。 |
| 双端呈现 | 小程序 `pages/requests` 和总部 `admin-web/app.js` 展示同一进度文案。保留总部意见，已抵扣的申请可进入对应账单。更新 `shared/request-projection.cjs`，首次审批通知说明当时仍需确认规则或核算费用。 |
| 岗位与跨端业务 | 用 `browser-round2.cjs` 复验个人账号交接，用 `browser-v343-task-routing.cjs`、工作电话和审批导出浏览器脚本查验权限，用 `browser-v34-finance.cjs` 复验停费到抵扣，用 `browser-remediation.cjs` 和微信开发者工具核对定位和补件。浏览器提供的坐标标作受控样例。 |
| 登录和消息 | 优先展示已接通的微信与手机验证码。个人一次性码确认预绑定的加盟商、一级管理员或总管理员身份。只在有未读时显示红点，用同一条申请记录核对结果。 |
| 加盟申请与网点 | 新增用户提交截图和总管理员核实到账、通过、退回的流程。以实际收款凭据编号去重，审核时创建待激活加盟账号。申请人与获批账号可看到自己的结果。列表和详情按日常办理、资料和历史分区。 |

回归以 `tests/acceptance-business.test.cjs` 与 `tests/browser-v34-finance.cjs` 覆盖政策未生效、待核算、待财务复核、待抵扣、抵扣入账。验证不存在或不属于当前网点的账单不能从申请跳转。所有业务状态、金额计算和岗位审批沿用现有合同。

交付前执行相关 Node 和总部 Chrome 回归、微信开发和生产构建、官方编译与模拟器。截图、请求号、迁移和 ZIP 校验结果进入本轮验收报告。正式平台身份、真实到账和独立用户试用按实际证据记录。
