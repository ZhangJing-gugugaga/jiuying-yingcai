## 实际修改

- `miniprogram/utils/api.js` 校验定位结果，保留精度 0 和手动定位的 null。以发出请求时的令牌核对失效会话，统一登录恢复流程，处理认证下载的 401。
- `miniprogram/utils/page.js` 按网点 ID 保留跨页选择，分页计数使用服务端结果，按域对象识别位置核验消息和申请消息。
- `miniprogram/pages/dashboard/index.js` 和 `miniprogram/pages/report/index.js` 以网点 ID 维持已选业务范围。月报更换网点或月份时清掉前一范围的表单值及审核摘要。
- `miniprogram/pages/report/index.wxml` 将检索入口留在空结果之外，让用户可以清除筛选。
- `miniprogram/pages/location/index.js`、`miniprogram/pages/location/index.wxml`、`miniprogram/pages/requests/index.js`、`miniprogram/pages/requests/index.wxml` 保留真实 GPS 来源、捕获时间和范围校验。位置核验提交使用后端已有的 `capturedAt` 顶层字段。
- `miniprogram/pages/support/index.js` 消息直达优先采用目标工单或会话 ID，列表已存在时复用同一条记录。
- `tests/acceptance-native.test.cjs` 新增 12 项回归。首批 10 项中有 9 项在原实现按预期失败，原实现的 Mock 支付取消已通过。第二批 2 项在修复前独立复现失败。

## 人工验收与后续工作包

1. 在微信开发者工具导入独立副本 `miniprogram`，接本地测试 API，以加盟商甲登录。进入月报，检索不存在的网点，清空并切换到株洲网点，下拉刷新后核对网点和招生不适用提示。看板以相同方式核对搜索后的选择。
2. 在具备平台授权的测试应用真机上复验地图选点、GPS 初次授权和拒绝、相机和相册、上传失败后重新上传。真机地理位置权限弹窗、地图服务可用性和系统设置行为在本记录中尚未实测。
3. 从消息分别进入位置信息、位置补件和其他客服工单，验证原生渲染与跳转。可用 Mock 支付取消后核对账单和实收。
4. 在正式配置的测试环境执行真实支付的取消、未完成和重查单，以及微信登录、隐私指引和发布门禁。平台资金、生产 AppID、服务域名及真机验收证据待补。
