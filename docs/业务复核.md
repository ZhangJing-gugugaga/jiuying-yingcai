# 九盈英才 V3.1 独立业务复核

> 历史资料。下文的“当前”“本轮”及验收数字均指报告出具时的版本。查阅 [V4.1 交接说明](handoff/00-开发交接总说明.md)了解现行范围及验收进度。

复核范围为 T06、T07、T08、T09、T10、T12、T13。验收对象是独立副本，测试使用回环 HTTP、本地 SQLite、开发身份和标明为 Mock 的支付。基线取 V3.1 的 02、06、07、14 至 19 及整改矩阵 P0-07/P0-08。本轮已实现并验证三项本地修复，正式部署、真实资金和未决制度另见下文。

## 症状与修复

## 边界与人工复核

- 历史月报更正或汇总调整批准后，当前实现将整月旧快照失效，再由管理层显式结算。测试覆盖旧版和调整前后值，不代表自动重算或正式的部分覆盖结算制度。
- 月报测试显式配置 5 日。基础月报提交仍按项目既有默认 5 日标记逾期，未配置的调度待办截止日期仍为 `null`，符合 P0-08 的提醒时间暂不硬编码边界。正式节假日、时刻、退款归期、统计可比变更和收费部分月规则仍待确认。
- 未执行微信真机、正式商户联调、真实入账或生产部署。当前金额均为本地验收数据。受控供应商边界测试和真机状态由总体验收另行记录。
- 人工复核在本地开发副本进行。加盟商在月报页依次保存草稿、提交、打开退回消息与待办。总部运营写明退回原因，随后批准新版。管理层在经营看板切换已审过程与已结算，结算前后分别导出并核对同一说明。财务在服务费以明确测试协议生成应收，模拟失败、取消和成功后检查独立实收，再审批指定金额和月份的暂停收费提案。

后续工作包为正式月报及部分覆盖结算制度签认、正式商户受控联调与资金对账、微信真机及跨端人工验收、正式环境确定后执行调度和数据量验证。
